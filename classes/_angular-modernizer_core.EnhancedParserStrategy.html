    Class EnhancedParserStrategy

    Enhanced Parser Strategy - ts-morph with preprocessing for complex projects.

    This parser is optimized for projects with custom patterns that standard ts-morph cannot handle directly. It provides preprocessing to:

    • Resolve custom path aliases (@shared/, @domain/, etc.)
    • Filter false positive syntax errors from external decorators
    • Handle complex constructor patterns

    Compatibility:

    • Projects with external decorators (e.g., @PageComponent)
    • Projects with custom path aliases (@shared/, @domain/)
    • Projects with complex constructor patterns
    • Standard Angular CLI projects (with overhead)
    • Projects requiring Babel parser (fallback to CustomParserStrategy)

    Reliability:

    • 0.8 base reliability (moderate)
    • -0.1 penalty for external decorators
    • -0.05 penalty for path aliases
    • -0.05 penalty for complex constructors
    • Minimum: 0.6 (still reliable for most transformations)

    Performance Characteristics:

    • Parse time: <5ms baseline + <1ms path resolution + <1ms false positive filtering
    • Total overhead: <10% vs StandardParserStrategy
    • Memory usage: ~50MB (single Project instance)
    • Preprocessing: Cached for performance

    Example: Basic usage

    const parser = new EnhancedParserStrategy(project);

    // Check if parser can handle project
    const context: ProjectContext = {
      projectRoot: '/path/to/project',
      hasCustomDecorators: true,
      hasPathAliases: true,
      hasComplexConstructors: false,
      angularVersion: '17.0.0'
    };

    if (parser.canHandle(context)) {
      const reliability = parser.getReliability(context); // 0.65
      const ast = await parser.parse('src/app/app.component.ts', fileContent);
      const result = await parser.transform(ast, [standaloneRule]);
    }

    Example: With custom configuration

    const parser = new EnhancedParserStrategy(project, {
      preserveAliases: true,      // Keep @shared/* as-is
      verboseLogging: true,       // Log preprocessing stats
      tsconfigPath: './tsconfig.app.json',
      baseDir: '/path/to/project/src'
    });

    parse

    • parse(file: string, content: string): Promise<ParserAST>

      Parse a file and return an Abstract Syntax Tree with preprocessing.

      This method implements the preprocessing pipeline:

      1. Path Alias Resolution: Resolve @shared/, @domain/, etc. to relative paths
      2. ts-morph Parsing: Parse preprocessed content with TypeScript compiler
      3. False Positive Filtering: Remove false positive syntax errors

      Preprocessing Steps:

      • Path aliases resolved before parsing (prevents "Cannot find module" errors)
      • False positives filtered after parsing (removes incorrect syntax errors)
      • External decorators detected and logged

      Error Handling:

      • Returns errors in AST.errors array (after filtering)
      • Never throws unless catastrophic failure
      • Preprocessing errors logged but don't block parsing

      Performance:

      • Parse time: <5ms baseline (ts-morph)
      • Path resolution: <1ms (cached)
      • False positive filtering: <1ms
      • Total: <7ms per file (<10% overhead vs standard)

      Parameters

      • file: string

        File path (used for error reporting and relative path calculation)

      • content: string

        File content to parse

      Returns Promise<ParserAST>

      Promise resolving to AST with SourceFile, diagnostics, and preprocessing metadata

      Example: Parse component with external decorators and path aliases

      const content = `
        import { SharedModule } from '@shared/modules';
        import { PageComponent } from '@shared/decorators/page';

        @PageComponent({ id: 'user-component' })
        @Component({ selector: 'app-user', template: '' })
        export class UserComponent {}
      `;
      const ast = await parser.parse('src/app/user.component.ts', content);
      console.info(`Path aliases resolved: ${ast.pathAliasesResolved}`); // 2
      console.info(`False positives filtered: ${ast.falsePositivesFiltered}`); // 1
      console.info(`Errors: ${ast.errors.length}`); // 0

      Example: Parse with syntax errors (genuine)

      const content = `
        import { Component } from '@angular/core';
        @Component({ selector: 'app-user' })  // Missing closing brace
        export class UserComponent {
      `;
      const ast = await parser.parse('user.component.ts', content);
      console.info(`Errors: ${ast.errors.length}`); // 1+ (genuine syntax error)
      ast.errors.forEach(err => console.error(`Line ${err.line}: ${err.message}`));

    transform

    • transform(
          ast: ParserAST,
          rules: TransformRule[],
      ): Promise<ParserTransformResult>

      Apply transformation rules to an AST.

      This method executes transformation rules on the parsed AST and returns the transformation result with metadata. Path aliases are preserved or resolved based on configuration.

      Transformation Process:

      1. Create transform context with sourceFile and project
      2. Execute each rule's transform() method
      3. Aggregate results (modified, changeCount)
      4. Detect syntax errors after transformation
      5. Return result with metadata (including preprocessing stats)

      Alias Handling:

      • If preserveAliases is true: Aliases are never resolved (preprocessing skipped)
      • If preserveAliases is false: Aliases are resolved before parsing (default)
      • No explicit "restore" needed - aliases are either preserved from start or resolved

      Error Handling:

      • Never throws errors
      • Returns result with modified=false on failure
      • Syntax errors after transformation reported in metadata

      Performance:

      • Transform time: <1s per file (typical)
      • No post-transformation preprocessing (aliases handled during parse)

      Parameters

      • ast: ParserAST

        Abstract Syntax Tree from parse()

      • rules: TransformRule[]

        Array of transformation rules to apply

      Returns Promise<ParserTransformResult>

      Promise resolving to transformation result

      Example: Simple transformation

      const ast = await parser.parse('component.ts', content);
      const rules = [standaloneRule];
      const result = await parser.transform(ast, rules);

      if (result.modified) {
        console.info(`Applied ${rules.length} rules`);
        console.info(`Changed ${result.changeCount} lines`);
        console.info(`Parser: ${result.metadata?.parserStrategy}`);
        console.info(`False positives filtered: ${result.metadata?.falsePositivesFiltered}`);
        console.info(`Output: ${ast.sourceFile.getFullText()}`);
      }

      Example: Handle transformation errors

      const result = await parser.transform(ast, rules);
      if (!result.modified && result.metadata?.syntaxErrors?.length) {
        console.error('Transformation introduced syntax errors:');
        result.metadata.syntaxErrors.forEach(err => console.error(`  - ${err}`));
      }
