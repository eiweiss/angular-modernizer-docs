    Class ImportDirectionViolationRule

    Import Direction Violation Rule (solid:import-direction-violation) - detects imports that cross conventional layer boundaries.

    Works without configuration: layers are inferred from path segments and tsconfig path aliases. Reports (violationType in the metadata):

    • forbidden-import-pattern: built-in forbidden directions (features importing shared or core, also through relative paths; libraries importing app or feature code)
    • layer-hierarchy: imports that go down the built-in order app > features > config > shared > core/lib/libs > assets/environments; imports from app, config and shared are exempt

    An import that matches a forbidden pattern is reported once, not also as a hierarchy violation. Layers are read from whole words of path segments and aliases. External packages and files whose layer cannot be determined are skipped.

    When the project configures a layer topology (layers or layersSource) the rule reports nothing: the config-driven LayerBoundaryViolationRule checks the imports against it.

    Example

    // Violation: a feature imports shared code
    // features/orders/order-list.component.ts imports from '@shared/format'
