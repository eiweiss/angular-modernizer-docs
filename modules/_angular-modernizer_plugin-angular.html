    Module @angular-modernizer/plugin-angular - v1.2.0

    Angular-specific analysis and transform rules for the Angular Modernizer kernel.

    The main entry point is AngularPlugin: register it with the kernel to get 28 analysis rules and 25 transform rules. The rule classes and their orchestrators are also exported for direct use, for example MissingOnPushRule, RxJSOptimizationRule, TypeSafetyAnalysisRule, ServiceBagTransformRule with ServiceBagTransformOrchestrator, and LibraryExtractionTransformRule with LibraryExtractionOrchestrator.

    Transform rules follow the "thin rule, thick orchestrator" pattern: the rule checks that its transformationType was requested in the plugin config (key @angular-modernizer/plugin-angular) and delegates the work to an orchestrator class.

    @angular-modernizer/plugin-angular

    Angular-specific analysis and transform rules for detecting and fixing anti-patterns, performance issues, and best practice violations in Angular applications.

    Overview

    This plugin provides 28 analysis rules and 25 transform rules (one per transformation type) for analyzing and modernizing Angular codebases, with a focus on:

    • Change Detection Strategy optimization
    • RxJS operator efficiency and memory leak prevention
    • Angular decorator validation
    • Component/Service architecture best practices
    • Automated code transformations (constructor injection, interface extraction, DI migration)

    Installation

    pnpm add @angular-modernizer/plugin-angular

    Analysis Rules

    RxJSOptimizationRule

    Rule ID: plugin-angular:rxjs-optimization Severity: Warning (per finding: subscribe-in-subscribe warning, the others info)

    Reports RxJS usage the syntax tree shows to be wrong or redundant. subscribe and pipe count when they are not declared in the project (RxJS, also without typings); comments and strings never decide a finding. Every finding carries metadata.violationType (operator-optimization), pattern, place (for example 'load' of class 'UserComponent'), principle and framework.

    Detected Patterns

    subscribe-in-subscribe (warning)

    A .subscribe() inside a callback of another .subscribe() (a function argument or a member of an observer object such as next). The inner subscription is not cancelled with the outer one. One finding per inner call, at that call.

    Before:

    this.route.params.subscribe((params) => {
      this.userService.getUser(params['id']).subscribe((user) => {
        this.user = user;
      });
    });

    After:

    this.user$ = this.route.params.pipe(
      switchMap(params => this.userService.getUser(params['id']))
    );

    // In template
    <div>{{ (user$ | async)?.name }}</div>
    duplicate-take-until (info)

    The same notifier in two takeUntil() of one pipe chain, also across .pipe(...).pipe(...). Keep one takeUntil() for the notifier, as the last operator.

    source$.pipe(takeUntil(this.destroy$), map(toView), takeUntil(this.destroy$));
    pipe-on-pipe (info)

    .pipe() called on the result of another .pipe(). Move the operators into the first pipe() call.

    Before:

    this.data$ = this.http
      .get('/api/data')
      .pipe(map((data) => data.items))
      .pipe(filter((items) => items.length > 0));

    After:

    this.data$ = this.http.get('/api/data').pipe(
      map((data) => data.items),
      filter((items) => items.length > 0),
    );

    Configuration

    The rule takes no options; rules['plugin-angular:rxjs-optimization'] accepts only suppressionComments, like every rule. The exported type RxJSOptimizationConfig is deprecated and not read (removed in 2.0).

    PerformanceViolationRule (deprecated)

    Rule ID: angular:performance-violation

    Deprecated, reports nothing, removed in 2.0. The id stays registered so configurations naming it keep loading; ConfigLoader warns when rules['angular:performance-violation'] is set. Subscriptions without cleanup are reported per subscription by architecture:rxjs-memory-leak (plugin-architecture).

    MissingOnPushRule

    Rule ID: angular:missing-onpush-change-detection Severity: Warning

    The only rule reporting components that should use OnPush. A component (Component or a parser.componentDecorators decorator) needs OnPush when it has an input (@Input() property, setter or getter, input(), input.required(), model(), inputs: metadata; its own or from an app base class), or when it has complex logic (more than 5 methods, a method over 10 lines, or ngOnInit, ngOnChanges, ngOnDestroy, ngAfterViewInit, ngAfterContentInit) and more than 3 dependencies (constructor parameters plus inject() fields, base classes included).

    • Without changeDetection: a warning at the class. From Angular 22 on (installed @angular/core, else the range in package.json) OnPush is the default, so nothing is reported.
    • With an explicit ChangeDetectionStrategy.Default or Eager: severity info at the changeDetection property. A project that marks its deliberate opt-outs hides these findings with a suppression comment, inline or on the line above:
    "rules": {
      "angular:missing-onpush-change-detection": { "suppressionComments": ["onpush-ignore"] }
    }

    Metadata: hasInputs, hasComplexLogic, dependencies, violationType (missing-onpush-strategy, explicit-default-strategy), strategy for the explicit case. Scope project (base classes live in other files).

    Before:

    @Component({
      selector: 'app-user-card',
      // Missing: changeDetection: ChangeDetectionStrategy.OnPush
    })
    export class UserCardComponent {
      @Input() user!: User;
    }

    After:

    @Component({
      selector: 'app-user-card',
      changeDetection: ChangeDetectionStrategy.OnPush,
    })
    export class UserCardComponent {
      @Input() user!: User;
    }

    AsyncPipeMisuseRule

    Rule ID: angular:async-pipe-misuse Severity: Warning

    Detects incorrect usage of the async pipe in templates. Two violation types:

    • double-async-subscription: observable used with | async in template AND manually subscribed in a lifecycle hook
    • multiple-async-subscriptions: same observable used with | async two or more times where the usages render together (different @if/@else or @switch branches do not count) and its source is not shared (share()/shareReplay() in its chain, or one member away: an own member or a member of an injected service, stateless operators after it allowed)

    The template is parsed, so HTML comments do not count. Findings point at the first usage in the template file.

    Known limitation: usages in different ng-templates that a template outlet picks between (*ngTemplateOutlet="cond ? a : b") count as rendering together, since the outlet condition is not evaluated.

    UnnecessaryChangeDetectionRule

    Rule ID: angular:unnecessary-change-detection Severity: Warning

    Detects detectChanges() calls (AST, not text) in a method, accessor, constructor or property initializer of a component without OnPush (explicit Default or Eager, or no changeDetection below Angular 22): default change detection already checks the component after every event. Only calls on the component's own ChangeDetectorRef count (this.cdr, or a name declared as ChangeDetectorRef or with inject(ChangeDetectorRef)); ref.changeDetectorRef.detectChanges() on a created or child view is needed and not reported. Calls in ngAfterViewInit, ngAfterContentInit, ngAfterViewChecked, ngAfterContentChecked and inside runOutsideAngular are needed and not reported, unless a nested zone.run callback brings the call back into the zone. One finding per member, metadata methodName, calls. Components that should use OnPush are reported by angular:missing-onpush-change-detection only.

    MissingReturnTypeRule

    Rule ID: angular:missing-return-type Severity: Warning

    Detects class methods, getters and function declarations without a return type annotation whose inferred return type is weak: it contains any (the type itself, a union member, a type argument such as Promise<any> or Observable<any>, an array or tuple element) or is unknown (the type itself or a union member). An inferred void, string or Observable<User> needs no annotation and is not reported, neither is unknown inside a type argument (Map<string, unknown>, written by the author), an any type argument that comes from a type parameter default (ElementRef<T = any>, this.form.get('x') returning AbstractControl<any, any>), an unresolved type, a lifecycle hook or a setter. This rule is the only one reporting missing return types; angular:type-safety reports none. Metadata: memberType (method, getter, function), inferredReturnType.

    Before:

    @Component({...})
    export class UserComponent {
      // Inferred return type: any
      parseSettings(raw: string) {
        return JSON.parse(raw);
      }

      // Inferred return type: string, not reported
      getUserName() {
        return this.user?.name || 'Unknown';
      }
    }

    After:

    @Component({...})
    export class UserComponent {
      // Explicit return type
      parseSettings(raw: string): UserSettings {
        return JSON.parse(raw);
      }

      getUserName() {
        return this.user?.name || 'Unknown';
      }
    }

    TypeSafetyAnalysisRule

    Rule ID: angular:type-safety Severity: Warning

    Reports explicit any (every any node except the targets of angular:any-to-interface), parameters without annotation that nothing types, and class properties without annotation whose inferred type is any, unknown, null, undefined or an array of any/never. Parameters count as untyped exactly where noImplicitAny would report them: a callback parameter typed by a contextual signature is not reported (items.map((p) => ...), new Promise((resolve) => ...), observer objects), also when that signature declares any (RxJS catchError, Promise.catch) or the callee is untyped (fix the any receiver there), nor is a setter parameter typed by its getter; a parameter of a method, function or constructor without annotation is. An any inside a JSDoc comment is not reported. Missing return types are reported by angular:missing-return-type only. metadata.violationType: explicit-any, untyped-parameter, untyped-property.

    AnyToInterfaceAnalysisRule

    Rule ID: angular:any-to-interface Severity: Warning

    Reports parameters and class properties typed any whose members are read by name (data.userId, this.item.name), with the members in metadata.accessedProperties and an interface name in metadata.suggestedInterfaceName; the any-to-interface transformation generates that interface. Not reported: any[], an any without members read by name or with only DOM event, array or string members, and an any an implementation repeats from the interface or base class member it implements (the contract is where the shape belongs). These nodes are not reported by angular:type-safety either, so every any node has one finding.

    Suppression comments: neither typing rule has a built-in marker. To hide any marked as intended, configure the marker for both rules:

    "rules": {
      "angular:type-safety": { "suppressionComments": ["any-ignore"] },
      "angular:any-to-interface": { "suppressionComments": ["any-ignore"] }
    }

    save(item: any /* any-ignore: untyped backend DTO */) { ... }
    // any-ignore: legacy plugin API
    definition: any;

    The any-to-interface transformation keeps an any with an any-ignore comment regardless of this setting.

    TooManyInputsRule

    Rule ID: angular:too-many-inputs Severity: Warning

    Detects components with more than 5 own inputs. Counted are @Input() properties and setters, signal input() / model() fields and inputs: metadata of the component decorator (also of decorators configured in parser.componentDecorators); inputs of base classes are not counted.

    Configuration:

    {
      "too-many-inputs": {
        "maxInputs": 5
      }
    }

    LifecycleHookRule (deprecated)

    Rule ID: angular:lifecycle-hook-violation

    Deprecated, reports nothing, removed in 2.0. The id stays registered so configurations naming it keep loading; ConfigLoader warns when rules['angular:lifecycle-hook-violation'] is set. Unhandled async errors in lifecycle hooks and other async entry points are reported by architecture:error-handling-pattern, subscriptions without cleanup by architecture:rxjs-memory-leak (both plugin-architecture).

    TemplateComplexityRule

    Rule ID: angular:template-complexity Severity: Warning

    Detects template bindings that run costly component code on every change detection run. The template is parsed with the Angular compiler; a finding needs a binding (interpolation, property, structural incl. ngTemplateOutlet context, @if/@for/@switch/@case/@let, @for track) that

    • calls a component method or function-valued property (m(), this.m()), or
    • reads a component getter,

    whose body runs a loop, an array scan (filter, map, find, some, reduce, sort, includes, ... on an array typed receiver, Object.keys/values/entries), parsing (new Date, Date.parse, JSON.parse/stringify, moment/dayjs, new RegExp, Intl, toLocale*) or a state write (assignment, ++/-- on this.x, .next/.set/.update/.push/.splice on a member), directly or in a component method it calls through this (one level, base classes included).

    Not reported: event bindings and $event, HTML comments, calls on other receivers (form.get(...), ctrl.hasError(...), item.x()), template variables, signals (signal, computed, input, model, toSignal, linkedSignal, viewChild, ...), members without a costly body, and cost behind services, pipes, static helpers or library code. A template file shared by several components gets one finding per position, reported with the first owner in path order (the rule declares scope: 'project', so a scan sees every owner, also across batches); the message names no class, metadata.owners lists the owners and metadata.costlyIn those whose member is costly. metadata.inLoop marks bindings inside an *ngFor/@for body (run once per item).

    Before:

    @Component({
      template: `<div>{{ activeCount() }}</div>`,
    })
    export class UserListComponent {
      users: User[] = [];

      activeCount(): number {
        return this.users.filter((u) => u.active).length;
      }
    }

    After:

    @Component({
      template: `<div>{{ activeCount() }}</div>`,
    })
    export class UserListComponent {
      users = signal<User[]>([]);
      activeCount = computed(() => this.users().filter((u) => u.active).length);
    }

    ImmutableInputViolationRule

    Rule ID: angular:immutable-input-violation Severity: Error

    Detects mutation of inputs that breaks OnPush change detection. Inputs are the component's own @Input() properties and setters and its inputs: metadata; signal inputs are read-only and left out.

    Before:

    @Component({
      changeDetection: ChangeDetectionStrategy.OnPush,
    })
    export class UserCardComponent {
      @Input() user: User;

      updateUser() {
        this.user.name = 'New Name'; // Mutates input - breaks OnPush
      }
    }

    After:

    @Component({
      changeDetection: ChangeDetectionStrategy.OnPush,
    })
    export class UserCardComponent {
      @Input() user: User;

      updateUser() {
        this.userChange.emit({ ...this.user, name: 'New Name' });
      }

      @Output() userChange = new EventEmitter<User>();
    }

    MissingTrackByRule

    Rule ID: angular:missing-trackby Severity: Warning

    Detects *ngFor without a trackBy function, and @for blocks that track object items by identity (track item). The template is parsed, so commented-out markup is not reported. An @for is reported only when the type checker proves the iterated component member holds objects (items, data.rows, a signal rows()); track $index, a tracked property (track item.id), primitive items and types that do not resolve (any, pipes, template variables) stay silent. Violation types: missing-trackby, for-identity-tracking. A template file shared by several components is reported once per loop, with the first owner in path order (the rule declares scope: 'project', so a scan sees every owner, also across batches); the message names no class, metadata.owners lists the owners and metadata.className is the first one.

    Before:

    @Component({
      template: `
        <li *ngFor="let user of users">{{ user.name }}</li>
      `,
    })
    export class UserListComponent {
      users: User[] = [];
    }

    After:

    @Component({
      template: `
        <li *ngFor="let user of users; trackBy: trackByUserId">{{ user.name }}</li>
      `,
    })
    export class UserListComponent {
      users: User[] = [];

      trackByUserId(index: number, user: User): string {
        return user.id;
      }
    }

    PresentationalComponentViolationRule

    Rule ID: angular:presentational-component-violation Severity: Info Scope: project

    Reports a component that is used as a template child but loads data itself. A component is a template child when another component's template uses it by selector (element or attribute), it has at least one input or output (@Input/@Output, setter inputs, input(), model(), output(), outputFromObservable(), decorator inputs/outputs, base classes included), and it is not routed, not created in code (dialogs, createComponent, portals, registries) and not a dialog. It loads data when a dependency reaches HttpClient (api injectedConcerns, kind data: also behind project services, injection tokens and abstract classes, base classes included). UI helpers that never reach HttpClient (translation, messages, progress, permissions) do not count. A registry entry counts as created in code only when the code ties the registry lookup to the component's selector; otherwise (a selector from data or a parameter) the component is still reported and the lookup sites are listed in metadata.registryCandidates. One finding per component at the class, with the data sources and template hosts in the message and in metadata.dataSources / metadata.hosts. Severity info: a child that loads its own data is a mixed role and often deliberate.

    Dialogs: the library dialog keys (MatDialogRef, MAT_DIALOG_DATA, DialogRef, DIALOG_DATA, MatBottomSheetRef, MAT_BOTTOM_SHEET_DATA) and components opened in code are never reported; rules['angular:presentational-component-violation'].dialogDetection (injectedClassNames, baseClassNames) adds project dialogs. actionTilePatterns is deprecated and has no effect. Subscriptions (owned by architecture:rxjs-memory-leak), class size (architecture:component-complexity), state fields and method names are not reported. Honors parser.componentDecorators.

    ServiceMutableStateRule

    Rule ID: angular:service-mutable-state Severity: Warning

    Detects @Injectable services that mutate public array, Map, or Set fields via push, splice, pop, sort, or reverse.

    PromiseObservableAnalysisRule

    Rule ID: angular:promise-vs-observable-anti-pattern Severity: Warning

    Reports code that turns Observables into Promises (metadata.type). Scope project; honors parser.componentDecorators; comments and strings never decide a finding.

    • toPromise: .toPromise() whose receiver is typed as an Observable, in any class or function (not a project class with its own toPromise), at the toPromise name. Message and suggestedFix follow the api sourceLifetime of the receiver: finite -> lastValueFrom(x) (same result), long-lived -> firstValueFrom(x) (toPromise would never resolve), otherwise lastValueFrom to keep waiting for completion, or firstValueFrom when the first value is meant. Metadata place, sourceLifetime (only inside a class).
    • promiseWrapperService: a method of an @Injectable class that returns a Promise (async or a Promise-like return type) and contains an HttpClient call; not reported when the method already has a toPromise finding. At the method name. Metadata methodName, place, httpLine.
    • sequentialAwait: exactly the await groups sequential-await-to-forkjoin converts (independent read awaits, same rules as the transform), in @Injectable and component classes, at the first await. Metadata awaitCount, methodName, place.

    No findings for async component methods or detectChanges() after an await.

    Transformation Rules

    ConstructorToInjectRule

    Transformation Type: constructor-to-inject

    Converts Angular constructor injection to the modern inject() function.

    Before:

    @Component({...})
    export class UserComponent {
      constructor(
        private userService: UserService,
        private router: Router,
        @Inject(APP_CONFIG) private config: AppConfig
      ) {}
    }

    After:

    @Component({...})
    export class UserComponent {
      private readonly userService = inject(UserService);
      private readonly router = inject(Router);
      private readonly config = inject<AppConfig>(APP_CONFIG);
    }

    Features:

    • Converts all constructor parameters to inject() calls
    • Keeps the @Inject(TOKEN) token (inject<T>(TOKEN)) and turns @Optional(), @Self(), @SkipSelf(), @Host() into inject() options; string tokens (@Inject('API_URL')) and other decorators keep the parameter, the rule message says why
    • Rewrites new X(a, b) in *.spec.ts / *.test.ts files into runInInjectionContext(Injector.create({ providers: [...], parent: TestBed.inject(EnvironmentInjector) }), () => new X()), so the specs keep compiling; they are saved and listed in changedFiles
    • Automatically adds inject import from @angular/core
    • Preserves parameter access modifiers and names
    • Makes a field readonly when it is never reassigned (api MemberWriteFinder: a private field is checked in its class, a protected or public one also through its references in the project, so a subclass assigning it keeps it mutable; templates are not checked); readonly parameters stay readonly; option readonlyInjectFields: false turns it off

    InterfaceExtractionRule

    Transformation Type: interface-extraction

    Extracts inline type literals into named interfaces.

    Before:

    @Component({...})
    export class UserFormComponent {
      @Input() user: {
        id: number;
        name: string;
        email: string;
        profile: {
          avatar: string;
          bio?: string;
        };
      };
    }

    After:

    interface UserProfile {
      avatar: string;
      bio?: string;
    }

    interface User {
      id: number;
      name: string;
      email: string;
      profile: UserProfile;
    }

    @Component({...})
    export class UserFormComponent {
      @Input() user: User;
    }

    Features:

    • Extracts complex inline type literals
    • Handles nested object types and arrays
    • Supports optional properties and union types
    • Generates unique interface names to avoid conflicts

    DependencyInjectionMigrationRule

    Transformation Type: dependency-injection-migration

    Converts constructor parameters with @Inject(TOKEN) to inject() fields (same helper as constructor-to-inject, other parameters stay) and modernizes ReflectiveInjector. String tokens (@Inject('API_URL')) stay unchanged with a reason: inject() takes no string token, and an InjectionToken is a different DI key than the string, so the providers have to switch first.

    Before:

    // Token injection
    @Injectable()
    export class ApiService {
      constructor(@Inject(API_URL) private apiUrl: string, private http: HttpClient) {}
    }

    // ReflectiveInjector usage
    const injector = ReflectiveInjector.resolveAndCreate([
      { provide: 'API_CONFIG', useValue: config },
    ]);

    After:

    @Injectable()
    export class ApiService {
      private readonly apiUrl = inject<string>(API_URL);

      constructor(private http: HttpClient) {}
    }

    // Modern injector usage
    const injector = Injector.create([{ provide: API_CONFIG, useValue: config }]);

    ConstructorInjectionTransformRule

    Transformation Type: constructor-injection-transform

    Converts field initializers x = new X(...) of a service or helper into x = inject(X) (shared with service-injection-cleanup through helpers/instantiation-to-inject.ts):

    • inject() is written only into classes with @Component, @Directive, @Injectable, @Pipe or @NgModule; anywhere else it would throw NG0203.
    • An @Injectable created without arguments becomes inject(X); without providedIn it enters the creating component's or directive's providers. With arguments it stays: inject(X) would ignore them.
    • An undecorated helper gets @Injectable() (no providedIn) and enters the creating component's providers, so each component keeps its own instance; only when every argument is an injected dependency of the component (this.x from a constructor parameter or inject(T) field) with the type of the helper's parameter.
    • A library class is converted only when its typings declare it injectable (static ɵprov) and it is created without arguments; other library classes (Map, FormGroup) are not touched.
    • Specs that construct a converted class with new run it in an injection context (runInInjectionContext(Injector.create({ providers: [], parent: TestBed.inject(EnvironmentInjector) }), () => new X())), or are named when the component provides the new dependency (only TestBed applies component providers).

    Every site left unchanged is named with its reason in the rule message.

    Before:

    export class GridHelper {
      constructor(private http: HttpClient) {}
    }

    @Component({ selector: 'app-grid', template: '' })
    export class GridComponent {
      private http = inject(HttpClient);
      private helper = new GridHelper(this.http);
      private audit = new AuditService(); // @Injectable({ providedIn: 'root' })
    }

    After:

    @Injectable()
    export class GridHelper {
      constructor(private http: HttpClient) {}
    }

    @Component({ selector: 'app-grid', template: '', providers: [GridHelper] })
    export class GridComponent {
      private http = inject(HttpClient);
      private helper = inject(GridHelper);
      private audit = inject(AuditService);
    }

    ComponentInputsInterfaceExtractionRule

    Transformation Type: component-inputs-interface-extraction

    Extracts the @Input() properties of a component into an interface <Class>Inputs that the component implements. The interface goes directly before the class (before its JSDoc and decorators), exported when the class is, in the indentation of the file, with the class type parameters the inputs use. An input without a type annotation gets its inferred type only when that is string, number or boolean; otherwise the component keeps its text and the rule message names the input. A class that already implements <Class>Inputs, or a file that declares it, is left alone, so a second run changes nothing.

    Before:

    @Component({...})
    export class UserCardComponent {
      @Input() userId!: number;
      @Input() userName = '';
      @Input() avatarUrl?: string;
    }

    After:

    export interface UserCardComponentInputs {
      userId: number;
      userName: string;
      avatarUrl?: string;
    }

    @Component({...})
    export class UserCardComponent implements UserCardComponentInputs {
      @Input() userId!: number;
      @Input() userName = '';
      @Input() avatarUrl?: string;
    }

    ServiceInjectionCleanupRule

    Transformation Type: service-injection-cleanup

    Converts manual service instantiation in field initializers and in assignments this.x = new X(...) directly in the constructor or ngOnInit to inject() fields, with the same rules as constructor-injection-transform (Angular-decorated classes only, @Injectable without arguments, helpers with @Injectable() and component providers). The field keeps its type (a ! is dropped), the assignment is removed, and an emptied constructor without parameters goes. A field initialized with new X() and assigned new X() again counts as one site. An assignment in another method stays (the method can run more than once), as does one to a member declared in a base class or assigned instances of different classes; each gets its reason in the rule message.

    Before:

    @Component({...})
    export class DataComponent {
      private audit!: AuditService;

      constructor() {
        this.audit = new AuditService();
      }
    }

    After:

    @Component({...})
    export class DataComponent {
      private audit: AuditService = inject(AuditService);
    }

    Additional Transformation Types

    The plugin also exposes the following transformation types via the transform-code MCP tool:

    • promise-service-to-observable - Converts @Injectable methods returning Promise<T> that await one Observable into Observable<T> methods (HttpClient calls get retry and catchError); the implemented project interface gets the same signature, and every caller in the project and its specs is wrapped in lastValueFrom(...) so it keeps its Promise (those files are changed too). Methods it cannot convert stay with the reason in the rule message
    • promise-component-to-reactive - Converts an async component method that only assigns awaited Observables to properties (this.p = await x.toPromise()) into a typed p$ Observable read with the async pipe in the template; needs a standalone component whose template (inline or a templateUrl file no other class uses) reads p exactly once, otherwise the method stays with a reason. The new text of a templateUrl file goes to TransformResult.fileChanges; transform-code saves and rolls it back
    • promise-cleanup - Replaces every x.toPromise() on an Observable with lastValueFrom(x); the Promise contract stays (lastValueFrom rejects with EmptyError on an Observable that completes without a value, where toPromise() resolved undefined)
    • sequential-await-to-forkjoin - Converts independent sequential read awaits (HttpClient get/head or project methods returning one) to one await firstValueFrom(forkJoin([...])) (components) or return firstValueFrom(forkJoin([...]).pipe(map(...))) (services); the method keeps its Promise contract, awaits that may change data keep their order
    • missing-output-transform - Adds a <method>Click = output<T>() signal to component methods that call business services and emits it at the end of the method; the method keeps its body. Methods returning a value stay (an emit would fire on every call). The rule message names the hosts that have to bind the new outputs; hosts are not changed
    • subscription-transform - Converts raw .subscribe() in lifecycle hooks to takeUntilDestroyed() pattern
    • library-extraction - Moves the artifacts into an Angular library imported as <libraryPrefix>/<libraryName> (use after extract-libraries detection): ng generate library runs asynchronously in a temporary workspace with a timeout (cliTimeoutMs) and the call's abort signal, the artifacts and their templates and styles move (originals deleted), every importer (relative, path alias, specs, barrels, import()) gets the import name, the entry file (lib.entryFile of ng-package.json) exports the moved files, secondaryEntryPoints get their own ng-package.json and public-api.ts, angular.json and every root tsconfig with paths get targeted edits. The rule writes nothing itself; all files are in changedFiles and restored by rollback. An artifact importing a file that stays in the app, a template outside its folder, a name clash, an existing target or a missing ng-packagr changes nothing, with the reason in the rule message
    • static-class-to-functions - Converts static-only utility classes to module-level functions and constants
    • extract-static-from-stateful - Moves public static methods of a stateful class to module-level functions above it
    • any-to-interface - Replaces any-typed parameters and properties with exported interfaces of the members read on them; the member types come from the type checker (where each value goes, and for a parameter the arguments callers pass), declared types keep their written text and types of other project files are imported. A target keeps any, with the reason in the rule message, when a member has no type or two types, is called or accessed further, the target is passed on as a typed value or carries an any-ignore comment
    • type-safety - Adds missing parameter, return and property types (implicit any becomes unknown)
    • dto-object-literal - Rewrites new X() followed by property assignments into an object literal with the class type (const r: X = { ... }); a class with a base class, decorators, constructor code or parameters, methods, accessors, defaults, non-public properties, an instanceof check in the project, or a required property the assignments leave out keeps its construction, with the reason in the rule message
    • interface-duplication - Consolidates the interface families of the requested file into a base interface plus one type alias per member (largest subset whose property types agree; the reason for every interface left out is in the rule message)
    • facade-pattern - Moves the business methods of a large component that only use injected dependencies word for word into <Name>Facade in <name>.facade.ts (@Injectable(), added to the component's providers); the component keeps delegating methods with the same signatures. Methods using component state stay, named in the rule message
    • form-modernization - Replaces FormBuilder calls (this._fb.group/control/array, any member name) with new FormGroup/FormControl/FormArray, including the [value, validators] shorthand of group and array entries; NonNullable or Untyped builders and entries typed any keep the class unchanged with a reason
    • container-presentational - Deprecated, changes nothing: making a component presentational moves its behavior to the hosts, which the transformation never changed. Use missing-output-transform and the analysis rule angular:presentational-component-violation
    • core-shared-modules - Deprecated, changes nothing: it never edited a file and only computed a project-wide report. Use the analysis tool analyze-core-to-shared; transform-code answers the type without loading the project
    • inheritance-to-composition - Pure base methods the derived classes of the file use move into <Base>Helper in <base>.helper.ts next to the base (created, providedIn: 'root', in changedFiles, removed by rollback) and leave the base; the derived classes inject and call it, callers through the derived type keep a delegating method, extends goes only when nothing else of the base is used; library and state-only bases, methods reading state and methods other classes use stay, with reasons in ruleMessages
    • service-bag-transform - Splits a Service Bag into focused services (rule ID refactor:service-bag-split)

    Each transform rule acts only when its type is requested: transform-code passes transformationType (and the call's options) under the '@angular-modernizer/plugin-angular' key of the transform config.

    Usage

    With MCP Tools

    # Start MCP server
    pnpm run mcp:start

    # Transform constructor injection
    transform-code --filePath src/app/user.component.ts --transformation constructor-to-inject

    # Extract interfaces
    transform-code --filePath src/app/data.models.ts --transformation interface-extraction

    # Migrate DI patterns
    transform-code --filePath src/app/legacy.service.ts --transformation dependency-injection-migration

    # Convert subscriptions to takeUntilDestroyed
    transform-code --filePath src/app/user.component.ts --transformation subscription-transform

    # Parallelize sequential awaits
    transform-code --filePath src/app/data.service.ts --transformation sequential-await-to-forkjoin

    With Direct API

    import { Kernel } from '@angular-modernizer/core';
    import { createPublicApi } from '@angular-modernizer/api';
    import { AngularPlugin } from '@angular-modernizer/plugin-angular';
    import { ContextFactory } from '@angular-modernizer/plugin-system';

    const plugin = new AngularPlugin();
    const kernel = new Kernel({ plugins: [plugin] });

    await kernel.initialize();

    // Get specific transformation rule
    const constructorToInjectRule = plugin
      .getTransformRules()
      .find((rule) => rule.id === 'angular:constructor-to-inject')!;

    // Transform a file; the rule acts only when its transformation type is set
    const project = kernel.getProject();
    const sourceFile = project.addSourceFileAtPath('user.component.ts');
    const context = ContextFactory.createTransformContext({
      sourceFile,
      project,
      api: createPublicApi(project),
      config: {
        '@angular-modernizer/plugin-angular': {
          transformationType: 'constructor-to-inject',
        },
      },
    });

    const result = await constructorToInjectRule.transform(context);

    if (result.modified) {
      await sourceFile.save();
    }
