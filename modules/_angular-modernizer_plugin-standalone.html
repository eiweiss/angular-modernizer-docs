    Standalone migration plugin for the Angular Modernizer.

    Migrates Angular components, directives and pipes to standalone. StandalonePlugin is the entry point for the kernel and registers StandaloneMigrationRule (standalone:migrate-to-standalone), which delegates to StandaloneMigrationOrchestrator. StandaloneMigrationReport is what a migration call returns; StandaloneMigrationConfig (deprecated) lists former options.

    @angular-modernizer/plugin-standalone

    Standalone migration plugin for the Angular Modernization Platform.

    Overview

    This package migrates Angular components, directives and pipes declared in NgModules to standalone. The plugin (StandalonePlugin, name @angular-modernizer/plugin-standalone) contributes one transform rule, StandaloneMigrationRule (ID standalone:migrate-to-standalone, transformation type standalone-migration), a thin rule that delegates to StandaloneMigrationOrchestrator.

    What the migration does

    Targets are the classes of the requested file with standalone: false (before Angular 19 also those without the flag). For an NgModule file, every class its declarations list is a target, so one call migrates a whole module.

    For each target:

    • Standalone flag: from @angular/core 19 on (version read from the nearest node_modules/@angular/core/package.json) standalone: false is removed, because standalone is the default; before 19, or when the version is unknown, standalone: true is written.
    • NgModules: every NgModule that declares the class imports it instead (moved from declarations to imports; an emptied declarations is removed). exports stay, so the other declarations of the module and the modules that import it keep the class in their scope. The NgModule stays.
    • Component imports: exactly the module imports whose exported components, directives and pipes the template uses. The template (inline or templateUrl) is parsed with @angular/compiler and its elements are matched with Angular's SelectorMatcher, pipes by name in every expression (interpolations, bindings, structural directives, @if / @for / @switch / @let, @defer triggers). Library modules are read from the compiled ɵmod declaration of their typings, project modules from their exports (also re-exported modules), standalone classes as themselves. Each used class is covered by the first module import that exports it; nothing is imported twice. X.forRoot() / X.forChild() is imported as X. A module import whose exports cannot be read (no compiled metadata, not an array, an expression) is kept and named in the message. The import statements copy the module file's specifiers (relative ones recomputed). A component that uses nothing gets no imports.
    • Siblings: a template that uses another declaration of its module that stays non-standalone keeps the class unchanged; the message names the siblings. Targets of the same call (an NgModule file) are imported directly. Targets whose templates use each other are kept with the reason (standalone classes that import each other need forwardRef), and so are targets that use a kept one.
    • Specs: TestBed.configureTestingModule({ declarations: [X] }) moves X into its imports.
    • Routes: unchanged (component: X works for standalone components).
    • Arrays: declarations, imports and exports are read as Angular flattens them: spreads, nested arrays, constants (also imported, as const included), forwardRef(() => X) (taken over as written into the component's imports). A class declared through a constant is removed from it only when the constant is used nowhere else (else kept with the reason); a module whose file names the class but whose declarations cannot be read keeps it unchanged (a standalone class in declarations is NG6008).
    • Commented flag: a comment after standalone: false on its line, or one above it that mentions standalone (// standalone-ignore: ...), keeps the class unchanged and is quoted in the reason; other comments above the flag stay before the next property.

    Directives and pipes get only the flag and the module change (@Directive and @Pipe have no imports).

    All edits happen in memory: the planning reads every type first, then the edits run, so the type checker is not rebuilt between them. transform-code saves every changed file (class, NgModules, specs), type-checks them and rolls them back as one change; changedFiles lists them. New text follows the file's style: quotes of its module specifiers and its indentation, else the nearest .prettierrc (JSON) or .editorconfig, else single quotes and 2 spaces.

    The result message (transform-code ruleMessages) lists the migrated classes with their imports, the declaring modules and updated TestBed modules, each kept class with its reason, and the module imports kept without known exports. modified is true when a class was migrated.

    Usage

    Through the MCP server:

    await callTool('transform-code', {
      filePath: '/app/src/app/toast/toast.module.ts', // or one component, directive or pipe
      transformation: 'standalone-migration',
      projectRoot: '/app',
    });

    Directly with the orchestrator:

    import { StandaloneMigrationOrchestrator } from '@angular-modernizer/plugin-standalone';
    import { ContextFactory } from '@angular-modernizer/plugin-system';
    import { createPublicApi } from '@angular-modernizer/api';
    import { Project } from 'ts-morph';

    const project = new Project({ tsConfigFilePath: 'tsconfig.json' });
    const sourceFile = project.getSourceFileOrThrow('src/app/toast/toast.component.ts');

    const report = await new StandaloneMigrationOrchestrator().run(
      ContextFactory.createTransformContext({ sourceFile, project, api: createPublicApi(project), config: {} }),
    );
    console.log(report.migrated, report.kept, report.message);
    await project.save(); // the class file, its NgModules and specs

    StandaloneMigrationConfig (autoAddCommonModule, autoAddFormsModule, preserveExistingImports) is deprecated and has no effect.

    Testing

    pnpm --filter @angular-modernizer/plugin-standalone test
    pnpm --filter @angular-modernizer/plugin-standalone build

    The package's Jest config uses the real @angular/compiler (no global mock, its ESM build compiled to CommonJS as in packages/api). The decision and scope tests build a ts-morph project with stubs of @angular/core and compiled library typings (ɵmod, ɵcmp, ɵpipe) and type-check the result. adapter-mcp transform-standalone*.e2e.test.ts run the migration through transform-code on temp git projects (changedFiles equals git status, tsc of app and spec configs, second run, rollback).
